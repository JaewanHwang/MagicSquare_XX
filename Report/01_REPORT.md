# MagicSquare_XX — Mom Test 문제 정의 보고서

> STEP 1 산출물 · Rob Fitzpatrick *The Mom Test* 방식 인터뷰 기반
> 작성일: 2026-06-04

## 페르소나
4×4 부분 마방진(빈칸 2개)을 커서 과제로 푸는 학습자.
1~16 숫자를 배치하고 모든 행·열·대각선의 합이 34인지를 **손으로** 검산함.

## 인터뷰 답변 (과거 사실)
- 지난주 커서 과제에서 빈칸 2개를 채우고 행·열·대각선 합을 맞췄다.
- 검산은 **한 줄씩 손으로 더해서** 했다.
- 대각선 하나를 빼먹어, 다 맞은 줄 알고 넘어갔다가 **나중에 틀린 걸 발견**했다.
- 그 일로 **20분을 날렸다**.
- 줄 하나를 빠뜨린 건 이번이 처음이 아니다(**전에도 있었다**) → 반복 패턴.

## 1. 표면 문제 (잘못된 정의 — 솔루션 섞임)
- "4×4 마방진 빈칸을 자동으로 채워주는 프로그램을 만든다"
- "행·열·대각선 합을 계산해주는 프로그램을 만든다"
- "검산 버튼/기능을 추가한다"

→ 모두 해결책이 박힌 문장이라 문제 정의로는 실격.

## 2. 진짜 문제 (한 문장)
**손으로 줄 단위 검산을 할 때 검사해야 할 10개 줄(4행·4열·2대각선) 중 하나를 빠뜨려도 즉시 판정되지 않아, 다 맞았다고 착각하고 넘어갔다가 뒤늦게 오답을 발견해 시간을 날린다.**

## 3. Mom Test 증거 3줄 (답변 인용)
1. "빈칸 2개 넣고 합 맞췄는데 대각선 하나를 빼먹어서 **20분 날렸다**" — 비용
2. "한줄씩 손으로 더해봤지" → "**나중에 대각선 하나가 틀린 걸 발견했어**" — 판정 지연
3. "(줄 빠뜨린 거) **전에도 있었어**" — 재현성(반복 패턴)

## 참고 — ECB 개념 분석 (문제인식 → 설계)
- **Entity**: `MagicSquare`(4×4 격자 데이터), `Cell`(각 칸 값·위치·상태), `SolveResult`(해결 결과)
- **Control**: `SquareValidator`(합 유효성 검증), `MissingFinder`(빈칸 위치 탐색), `Solver`(완성 알고리즘)
- **Boundary**: `GridUI`(격자 시각화), `InputHandler`(사용자 입력), `ResultDisplay`(결과 표시)
