## 3. ECB 계층 구조
```
src/
├─ boundary/   # 입출력·검증 (E001~E007 오류 처리)
├─ control/    # 흐름·조합 (Validator/Finder/Solver 흐름)
└─ entity/     # 순수 도메인 (E001~E005 처리 금지, import 금지: entity → *)
tests/
├─ boundary/   # UI Track (U-*, test_u_*) — Mock 허용
├─ control/    # Logic Track (D-*, test_d_*) — Domain Mock 금지
└─ entity/     # Logic Track (D-*, test_d_*) — Domain Mock 금지
```
- 의존 방향: `boundary → control → entity` (단방향).
- `entity`는 어떤 계층도 import 하지 않는다.

## 4. Dual-Track TDD 매핑
| Track | 대상 계층 | 테스트 ID | 파일명 | Mock |
| --- | --- | --- | --- | --- |
| Logic | entity, control | `D-*` | `test_d_*.py` | 금지(실제 객체) |
| UI | boundary | `U-*` | `test_u_*.py` | 허용 |

## 5. 도메인 불변식 (구현 시 준수)
- 4×4 격자, 빈칸(0) 정확히 2개, 채워진 값 1~16(중복 불가).
- 마방진 상수 `MAGIC_SUM = 34` — SSOT로 단일 관리(리터럴 산재 금지).
- 정답 출력: `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 1-index.
- 오류 코드 E001~E007은 boundary 전용, entity는 E001~E005 처리 금지.

## 6. 검증
